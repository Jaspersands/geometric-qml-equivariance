# geometric-qml-equivariance

Variational circuits that conserve total spin: their Lie algebras, their gradients, and the models they are meant for.

[![CI](https://github.com/Jaspersands/geometric-qml-equivariance/actions/workflows/ci.yml/badge.svg)](https://github.com/Jaspersands/geometric-qml-equivariance/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](LICENSE)

Gates generated by the exchange operators $G_{ij} = X_iX_j + Y_iY_j + Z_iZ_j$ commute with total spin. A circuit built from them, started in a product of singlets, stays in the $S = 0$ sector, whose dimension is a Catalan number rather than $2^N$. This package measures what that constraint buys:
- the dimension of the circuit's dynamical Lie algebra, checked against a closed form up to eight qubits
- how gradient variance shrinks with system size
- ground-state searches for Heisenberg models and the Fermi–Hubbard chain

It also covers compiling these circuits to native gates.

[Interactive page](web/index.html): an eight-qubit statevector simulator in the browser, with the sampling and Lie algebra closures running in a background worker.

## The Lie algebra

By Schur–Weyl duality the exchange operators span the commutant of SU(2). Their Lie closure is $\bigoplus_S \mathfrak{su}(m_S)$ plus one central element, so

$$\dim \mathfrak g = \sum_S (m_S^2 - 1) + 1, \qquad m_S = \binom{N}{N/2 - S} - \binom{N}{N/2 - S - 1}.$$

The closure code gives 1, 12, 129 and 1426 for chains of 2, 4, 6 and 8 qubits, matching the formula, while hardware-efficient circuits generate all of $\mathfrak{su}(2^N)$ (15, 63, 255). Because $m_S$ grows like a Catalan number, this algebra is exponentially smaller than $\mathfrak{su}(2^N)$ but not polynomial in $N$. Avoiding barren plateaus entirely needs more symmetry, for example permutation invariance.

The closure is computed efficiently in two ways. Because the algebra is spanned by nested commutators $[g_1,[g_2,\dots g_k]]$, each round commutes only the generators with the newest elements: $n_g D$ commutators instead of $D^2$. For SU(2)-invariant generators it can also run on the Schur multiplicity blocks: 1 430 numbers per element at $N = 8$ instead of 65 536.

## Modules

| Module | Contents |
|---|---|
| `models` | Lattices (chain, ring, grid, triangular ladder, and kagome on $L_x \times L_y$ unit cells), Heisenberg models built as sparse matrices, SU(2) generators, spin multiplicities |
| `ansatz` | Equivariant, hardware-efficient and QAOA circuits, each with a PennyLane circuit, its generators and a NumPy unitary |
| `dla` | Lie algebra closure (generator-frontier algorithm, batched orthonormalisation), the SU(2)-reduced representation, the closed-form dimension |
| `barren_plateau` | Gradient variance at random parameters and its scaling with $N$, at fixed depth or depth $L = N$ |
| `vqe` | Variational ground-state search with a singlet-purity diagnostic |
| `fermi_hubbard` | Sparse Jordan–Wigner Fermi–Hubbard chain, spin and η-pairing SU(2) generators, Lanczos ground states in fixed $(N, S_z)$ sectors |
| `qgnn` | A graph network whose layers are exponentials of the graph Heisenberg Hamiltonian; exact, or Trotterised into native exchange gates |
| `sycamore_transpile` | Exchange gates as FSim plus CNOT·Rz·CNOT, with a snake placement that puts every chain bond on a coupler |
| `export_openfermion` | Hamiltonians as JSON, OpenFermion and Qiskit term lists |
| `cli` | `geometric-qml variance | dla | sectors | transpile | vqe | benchmark` |

## Examples

```python
import numpy as np
from geometric_qml import (
    HeisenbergSpinChain, EquivariantQuantumAnsatz, HardwareEfficientAnsatz, FermiHubbardChain,
    analyze_ansatz, equivariant_dla_dimension_formula, run_barren_plateau_scaling_study,
)
from geometric_qml.dla import equivariant_dla_dimension_by_closure
from geometric_qml.qgnn import QuantumGraphNeuralNetwork

# Lie algebra dimensions against the closed form
print(analyze_ansatz(EquivariantQuantumAnsatz(n_qubits=6, n_layers=1, weight_sharing=False))["dla_dimension"])  # 129
print(equivariant_dla_dimension_by_closure([(i, i + 1) for i in range(7)], 8)["dla_dimension"])               # 1426
print(equivariant_dla_dimension_formula(8))                                                                    # 1426

# Gradient variance with depth growing as N: hardware-efficient decays faster
study = run_barren_plateau_scaling_study(qubit_list=[4, 6, 8, 10], depth="linear", n_samples=30)
print(study["fits_mean"]["hea"]["slope_log2"], study["fits_mean"]["equivariant"]["slope_log2"])   # about −0.72, −0.38

# The 12-site kagome torus (every site has four neighbours)
print(HeisenbergSpinChain(12, lattice_type="kagome", periodic_boundary=True).exact_ground_state()[0] / 48)  # −0.45374

# Fermi–Hubbard, 8 sites at half filling (16 qubits, sparse)
print(FermiHubbardChain(n_sites=8, on_site_u=4.0).ground_energy(n_particles=8, sz=0.0))            # −4.23581

# A graph-network layer compiled to native exchange gates
ring = np.roll(np.eye(6), 1, axis=1); ring = ring + ring.T
q = QuantumGraphNeuralNetwork(ring, n_layers=2, trotter_steps=8)
print(q.su2_equivariance_error([0.3, 0.1, 0.5, 0.2]), q.equivariance_error([0.3, 0.1, 0.5, 0.2], [1, 2, 3, 4, 5, 0]))
```

```bash
geometric-qml dla --ansatz equivariant --qubits 8
geometric-qml sectors --qubits 8
geometric-qml benchmark --quick
```

## Notes

- The variance of a shared angle that multiplies a sum over N − 1 bonds grows with N, so the study reports the variance per bond and compares scaling exponents rather than raw values.
- Barren plateaus appear when depth grows with N. At fixed shallow depth nothing plateaus, and at N = 2 the equivariant cost is constant because the singlet is the only S = 0 state.
- Trotterisation keeps SU(2) equivariance exact, because every native exchange gate commutes with total spin. Permutation equivariance becomes approximate, with an error falling as $1/r^2$ in the number of Trotter steps; `equivariance_error` measures it.
- The Sycamore transpiler uses FSim gates with arbitrary angles. Hardware exposes one calibrated angle; the companion `cirq-fsim-compiler` handles that case.
